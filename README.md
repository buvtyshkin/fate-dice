# Fate Dice для SillyTavern

Честный внешний бросок, который игрок включает вручную на конкретный ход. Модель получает готовое число и правило, как его читать. Пресет не меняется.

## Установка

Папка расширения лежит в `data/default-user/extensions/fate-dice`. Перезапуск Таверны не нужен: обновите страницу (Ctrl+F5).

## Как пользоваться

1. Кнопка с кубиком у поля ввода: нажал — взведена, кубик горит золотым.
2. Отправил сообщение: в его конец дописалась пометка `[🎲 Судьба: 12/18]`, кнопка сбросилась. В настройках кнопку можно сделать залипающей: тогда бросок идёт на каждое сообщение, пока не снимешь.
3. Пока пометка стоит в последнем ходе игрока, модель перед каждой генерацией получает правило. Свайп, регенерация и continue число не меняют: оно лежит в сообщении и сохранено вместе с чатом.

Пометку можно править руками, как обычный текст: следующая генерация прочитает новое число. Удалил пометку — правила больше нет.

`/fate` дописывает пометку к тексту в поле ввода без кнопки, например из Quick Reply. Команда возвращает текст пометки. Если пометка в поле уже есть, второго броска не будет.

## Настройки

Extensions → 🎲 Fate Dice.

- **Включено** — глобальный выключатель. Выключено: нет кнопки, нет `/fate`, правило не вставляется, даже если в чате есть пометки.
- **Залипающая кнопка** — по умолчанию одноразовая.
- **Кубик** — формула NdM, по умолчанию `3d6`. Шкалу в тексте правила при смене кубика правь сам.
- **Шаблон пометки** — `{{fate}}` это число, `{{fate_max}}` максимум. Правило узнаёт пометку только по виду `[🎲 … число/число]`. Если шаблон ему не подходит, панель предупредит.
- **С новой строки** — иначе пометка идёт через пробел.
- **Правило для модели** — многострочный текст. Подставляются `{{fate}}`, `{{fate_max}}` и обычные макросы вроде `{{user}}`. В правиле по умолчанию самого числа нет: модель видит его в пометке.
- **Роль правила** — system или user.

## Как это устроено

- **Бросок** — `crypto.getRandomValues`, без перекоса от деления по модулю.
- **Пометка** дописывается в `chat[id].mes` в обработчике `MESSAGE_SENT`. Таверна вызывает это событие после сохранения сообщения, но до его отрисовки и сборки промпта, поэтому способ отправки не важен: кнопка, Enter, телефон, `/send`. Если пометка в сообщении уже есть, новый бросок не делается.
- **Правило** ставит `setExtensionPrompt` на depth 0. Состояние пересчитывается на `GENERATION_AFTER_COMMANDS` (каждая генерация) и на `MESSAGE_SENT` (при обычной отправке новый ход появляется только к этому моменту). Ищется последнее сообщение игрока, скрытые не считаются.
- **Кэш.** Системный префикс и ранняя история не меняются: правило живёт только на depth 0, а пометка в старом ходе — неизменная часть его текста.
- **Reasoning.** Ничего не вставляется и не запрашивается.
- Impersonate и quiet-запросы (саммари и прочие служебные) правило не получают: это не ответ на ход игрока.
